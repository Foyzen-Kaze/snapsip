## Historia
Como Encargado de Despacho, quiero registrar el universo completo de piezas de un proyecto a partir del plano o archivo de piezas, para que el sistema las registre automáticamente en estado Pendiente, organizadas por parte de la casa.

## Flujo de interacción
Reconstruido desde el Gherkin y CU-03 (sin DSS propio):

1. El **Encargado de Despacho** abre un proyecto que está en estado **«Sin piezas cargadas»**, con las partes definidas al crearlo y sin piezas.
2. El sistema le muestra el botón **«Inyectar piezas desde plano/archivo»** solo en ese proyecto y con ese rol.
3. El Encargado pulsa el botón; no selecciona ni carga ningún archivo real.
4. El sistema toma esas `ParteCasa` y sus `cantidad_prevista`, y genera los códigos aleatorios únicos dentro del proyecto para las piezas de cada parte (total 1–100).
5. El sistema persiste, en una sola operación, las `Piezas` en estado **«Pendiente»** y sin torre dentro de las partes existentes, cambia el proyecto a **«En preparación»** y oculta el botón.
6. El sistema muestra cuántas **partes** y cuántas **piezas** se crearon. Un nuevo intento se rechaza sin modificar datos.

**Variantes:**
- Si otro rol intenta la operación, el sistema la **rechaza sin modificar datos** (HU-01 CA3).
- Si el proyecto no está en «Sin piezas cargadas» (o ya tiene piezas), el botón **no se muestra** y no se modifica nada.
- **CA2** (formato inválido / filas incompletas) **no se representa en la demo**: es una desviación documentada, igual que CA2 de HU-01.

## Escenarios Gherkin (actualizados el 2026-11-26 con la decisión OBS-1; CA2 se mantiene como desviación documentada)
```gherkin
Característica: Inyectar piezas desde plano/archivo

  # CA1
  Escenario: Inyección de piezas desde un archivo válido
    Dado que un proyecto se encuentra en estado "Sin piezas cargadas" y tiene las partes de la casa definidas al crearlo
    Y el plano/archivo contiene las piezas organizadas por esas partes
    Cuando el encargado de despacho solicita inyectar las piezas desde ese archivo
    Entonces el sistema crea en una sola carga exactamente la cantidad prevista de piezas por parte
    Y asocia cada pieza a su parte de la casa ya registrada dentro del proyecto
    Y establece cada pieza en estado "Pendiente" y sin torre asignada
    Y cambia el proyecto a estado "En preparación"
    Y oculta el botón «Inyectar piezas desde plano/archivo»

  # CA1
  Escenario: Rechazo de un reintento de inyección
    Dado que un proyecto ya fue inyectado y está en estado "En preparación"
    Cuando el encargado de despacho solicita inyectar piezas de nuevo
    Entonces el sistema rechaza la solicitud
    Y comunica que el proyecto ya tiene piezas inyectadas y que no se modificaron datos
    Y no modifica piezas ni partes de la casa

  # CA2
  Escenario: Rechazo de un archivo con formato inválido
    Dado que un proyecto se encuentra en estado "Sin piezas cargadas"
    Cuando el encargado de despacho solicita inyectar las piezas desde un archivo que no cumple la plantilla definida
    Entonces el sistema rechaza la carga completa
    Y comunica que el formato no es válido
    Y no registra piezas ni modifica las partes definidas al crear el proyecto
    Y mantiene el proyecto en estado "Sin piezas cargadas"

  # CA2
  Escenario: Rechazo de un archivo con filas incompletas
    Dado que un proyecto se encuentra en estado "Sin piezas cargadas"
    Y el archivo de piezas contiene filas sin datos obligatorios
    Cuando el encargado de despacho solicita inyectar las piezas desde ese archivo
    Entonces el sistema rechaza la carga completa
    Y señala las filas con error
    Y no registra piezas parciales
    Y mantiene el proyecto en estado "Sin piezas cargadas"
```

## Supuestos
- **Simulación de la demo:** el botón «Inyectar piezas desde plano/archivo» reemplaza la selección de archivo. No existe carga real, lectura de plantilla ni validación de formato; el generador aleatorio produce datos válidos por construcción.
- **Desviación documentada:** CA2 del Gherkin (formato inválido, filas incompletas) no se implementa ni se prueba con el generador; queda registrada en `.cin324/validaciones/VAL-HU-03-1.md`, igual que CA2 de HU-01.
- **Partes definidas al crear proyecto (OBS-1):** el proyecto nace en «Sin piezas cargadas» con las partes de la casa creadas por HU-02 (cantidades enteras no negativas, total 1–100) y cero piezas. La inyección es una acción posterior y explícita del Encargado de Despacho.
- **Aleatoriedad acotada:** hasta 100 piezas en total, al menos una por parte con cantidad positiva; los nombres de las partes vienen de HU-02, no se eligen al azar en HU-03; código de pieza único dentro del proyecto, con formato letra A–Z y número 1–25 (al azar, sin repetir el código completo dentro del proyecto; se permite repetir en proyectos distintos).
- **Aplicación de taller:** web sencilla, SQLite, sin autenticación real ni infraestructura extra; rige el selector de rol de demostración de HU-01.
