## Flujo de interacción (reconstruido; sin DSS)
1. El Operario accede con el rol Operario de Bodega, según el mecanismo de acceso de HU-01.
2. El Operario abre la consulta de piezas pendientes (ruta propia, p. ej. `/pendientes`); el sistema ofrece cada proyecto **por su cliente y su código** (CA3). No se reutiliza `/proyectos`, que está restringido al Encargado de Despacho (`src/rutas/proyectos.ts:9-12`).
3. Al seleccionar un proyecto: si está en estado **«Sin piezas cargadas»**, el sistema informa que el proyecto no tiene partes de la casa con piezas cargadas y termina (CA6); si no, ofrece **únicamente** las partes que tienen piezas cargadas (CA4, CA5).
4. Si no se eligió parte, el sistema **pide elegirla** y no muestra resultados ni el mensaje «0 pendientes».
5. Con proyecto y parte elegidos, el sistema presenta solo los `codigo` de las piezas en estado **«Pendiente»** de esa parte; excluye piezas de otras partes y las que no están «Pendiente» (CA1).
6. Si la parte elegida no tiene piezas pendientes, el sistema comunica explícitamente **«0 pendientes»** para esa parte (CA2).
7. Variante: otro rol intenta consultar → el sistema rechaza el acceso sin mostrar datos (HU-01 CA3).

**Variantes:**
- Proyecto en «Sin piezas cargadas»: aviso de que no hay partes con piezas cargadas (CA6).
- Proyecto con piezas solo en algunas partes: el selector ofrece únicamente esas partes (CA4, CA5).
- Sin parte elegida: pedir la selección; **no** es un caso de «0 pendientes».
- Parte elegida sin pendientes: «0 pendientes» para esa parte.
- Rol distinto de Operario de Bodega: rechazo sin modificar ni mostrar datos.
